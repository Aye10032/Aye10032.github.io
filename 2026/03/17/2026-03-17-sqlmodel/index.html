SQLModel中的一对多与多对多数据表

模型设计：用户、文章与标签

在这个例子中，我们设计了一个简单的多表模型。它假装模拟一个博客系统，其中：

  • User (用户) -> Post (文章)：一对多。用户删了，文章必须一起消失（级联）。
  • Post (文章) -> Tag (标签)：多对多。一篇文章有多个标签，一个标签下有多个文章。

作为参考，这一定义对应的SQL建表如下：

关键字段解释

在我们的示例数据中，各个数据表下有以下字段：

  • User: 属性有 id, username, posts
  • Post: 属性有 id, title, author_id, author, tags
  • Tag: 属性有 id, name, posts
  • PostTagLink: 中间表，属性有 post_id, tag_id

数据库物理约束 (Field)

foreign_key (外键连接)

用在子表中，格式是 目标表名.字段名

  • 具体代码： author_id: int = Field(foreign_key="users.id")，这里的 users 是 User 类的 __tablename__。
  • 实际作用： 在数据库 posts 表里创建一列叫 author_id，强制要求这里填的数字必须是 users 表里真实存在的 id。

ondelete 删除策略

与外键配合使用，当外键对应的父表数据删除时，这张表中对应数据如何处理

  • 具体代码： Field(foreign_key="users.id", ondelete="CASCADE")
  • CASCADE： 数据库层面的“连坐”。当在数据库里删掉 ID 为 1 的用户时，数据库引擎会自动扫描 posts 表，把所有 author_id 为 1 的文章一并删除。
