# SQLModel中的一对多与多对多数据表

## 模型设计：用户、文章与标签

在这个例子中，我们设计了一个简单的多表模型。它假装模拟一个博客系统，其中：

*   **User (用户) -> Post (文章)**：一对多。用户删了，文章必须一起消失（级联）。
*   **Post (文章) -> Tag (标签)**：多对多。一篇文章有多个标签，一个标签下有多个文章。

```python
import uuid
from datetime import datetime, UTC
from typing import Optional, List
from sqlmodel import SQLModel, Field, Relationship, Column, ForeignKey, String

# --- 1. 多对多中间表 ---
class PostTagLink(SQLModel, table=True):
    __tablename__ = "post_tag_links"
    # ondelete="CASCADE" 确保当文章或标签被删时，中间表的关联记录自动清理
    post_id: uuid.UUID = Field(foreign_key="posts.id", primary_key=True, ondelete="CASCADE")
    tag_id: int = Field(foreign_key="tags.id", primary_key=True, ondelete="CASCADE")

# --- 2. 标签表 ---
class Tag(SQLModel, table=True):
    __tablename__ = "tags"
    id: Optional[int] = Field(default=None, primary_key=True)
    name: str = Field(unique=True, index=True) # index=True 提高查询效率

    # 多对多关系：使用 link_model 指向中间表
    posts: List["Post"] = Relationship(back_populates="tags", link_model=PostTagLink)

# --- 3. 用户表 ---
class User(SQLModel, table=True):
    __tablename__ = "users"
    id: int = Field(default=None, primary_key=True)
    username: str = Field(index=True)
    
    # 一对多：设置 cascade_delete=True
    # 当 session.delete(user) 时，会自动寻找并删除该用户的所有 posts
    posts: List["Post"] = Relationship(back_populates="author", cascade_delete=True)

# --- 4. 文章表 ---
class Post(SQLModel, table=True):
    __tablename__ = "posts"
    id: uuid.UUID = Field(default_factory=uuid.uuid4, primary_key=True)
    title: str
    content: str
    
    # 外键：指向 User
    # 物理级联：ondelete="CASCADE" 保证即便不通过 Python 删，数据库也会自动清理
    author_id: int = Field(foreign_key="users.id", ondelete="CASCADE")
    
    # 关系属性
    author: User = Relationship(back_populates="posts")
    
    # 多对多：同样需要 link_model
    tags: List[Tag] = Relationship(back_populates="posts", link_model=PostTagLink)
    
    created_at: datetime = Field(default_factory=lambda: datetime.now(UTC))
```

作为参考，这一定义对应的SQL建表如下：

```sql
-- 1. 创建用户表 (User)
CREATE TABLE users (
    id SERIAL PRIMARY KEY,
    username VARCHAR(255) NOT NULL
);

-- 2. 创建标签表 (Tag)
CREATE TABLE tags (
    id SERIAL PRIMARY KEY,
    name VARCHAR(255) NOT NULL UNIQUE
);

-- 3. 创建文章表 (Post)
CREATE TABLE posts (
    id UUID PRIMARY KEY DEFAULT gen_random_uuid(),
    title VARCHAR(255) NOT NULL,
    content TEXT NOT NULL,
    author_id INTEGER NOT NULL,
    created_at TIMESTAMPTZ NOT NULL DEFAULT NOW(),

    -- 物理级联删除：ON DELETE CASCADE
    CONSTRAINT fk_author 
        FOREIGN KEY (author_id) 
        REFERENCES users (id) 
        ON DELETE CASCADE
);

-- 4. 创建多对多中间表 (PostTagLink)
CREATE TABLE post_tag_links (
    post_id UUID NOT NULL,
    tag_id INTEGER NOT NULL,
    
    -- 复合主键
    PRIMARY KEY (post_id, tag_id),
    
    -- 关联文章的物理级联
    CONSTRAINT fk_post 
        FOREIGN KEY (post_id) 
        REFERENCES posts (id) 
        ON DELETE CASCADE,
        
    -- 关联标签的物理级联
    CONSTRAINT fk_tag 
        FOREIGN KEY (tag_id) 
        REFERENCES tags (id) 
        ON DELETE CASCADE
);
```



## 关键字段解释

在我们的示例数据中，各个数据表下有以下字段：

- **User**: 属性有 `id`, `username`, `posts`
- **Post**: 属性有 `id`, `title`, `author_id`, `author`, `tags`
- **Tag**: 属性有 `id`, `name`, `posts`
- **PostTagLink**: 中间表，属性有 `post_id`, `tag_id`



### 数据库物理约束 (Field)

#### `foreign_key` (外键连接)

用在子表中，格式是 `目标表名.字段名`

- **具体代码：** `author_id: int = Field(foreign_key="users.id")`，这里的 `users` 是 `User` 类的 `__tablename__`。
- **实际作用：** 在数据库 `posts` 表里创建一列叫 `author_id`，强制要求这里填的数字必须是 `users` 表里真实存在的 `id`。



#### `ondelete` 删除策略

与外键配合使用，当外键对应的父表数据删除时，这张表中对应数据如何处理

- **具体代码：** `Field(foreign_key="users.id", ondelete="CASCADE")`
- **CASCADE**： 数据库层面的“连坐”。当在数据库里删掉 ID 为 1 的用户时，数据库引擎会自动扫描 `posts` 表，把所有 `author_id` 为 1 的文章一并删除。



### Relationship
